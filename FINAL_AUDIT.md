## 8. Remaining limitations

1. **M3 residual (5,900 km)** — passes threshold but extremely close (98.3%). Not a numerical issue — physically limited by 3-body model missing Jupiter perturbation. Adding Venus+Jupiter+Saturn would reduce residual by ~5×.
2. **M4 validation** — numerical verification is local moon-centric two-body, not mission-level N-body. Does not validate the complete Earth–Moon transfer phase.
3. **M6 r_p accuracy** — best-by-dv window (MJD 61154.0) has 8.33% r_p error. Best-balanced window (MJD 61066.0) has 5.2% error. Neither is below 5%; an iterative correction loop would be needed for higher precision.
4. **M7 convergence order** — not well-defined because the trajectory solver's r_p response is non-smooth (depends on lunar intercept geometry). Energy drift fully converged.
5. **No three-dimensional extension** — all main results use J2000 2D projection (ecliptic plane). O1 not implemented.
6. **No relativistic correction** — O2 not implemented.
7. **Animation (O5)** — 45s MP4 (h264, 24fps) generated via matplotlib + ffmpeg. Falls back to GIF if ffmpeg missing. MP4 不进入 Git。Not in `make all`.
8. **Differential corrector (O3)** — upgraded from 1-param to multi-param damped Gauss-Newton with Jacobian, line search, Tikhonov fallback, multi-start. **Sanity audit caught a target-leakage bug**: the earlier 3.87e9x "convergence" was invalid — tof_shift changed rocket time but target epoch was fixed. With correct physics (target recomputed per eval), improvement is ~4x (918k→248k km). The corrector framework is complete and no-scipy, but the position-shooting problem is hard with only 2-3 parameters. Status: done-with-caveat.
9. **Multi-gravity assist (O4)** — preliminary patched-conic chain exploration with analytic Venus fallback. Of ~8400 grid combinations, 98 had all 3 Lambert legs converge (retained for analysis). None reached feasible-ish status due to Moon/Venus flyby turn deficit at high v_inf. Chain not demonstrated as feasible in patched-conic framework.

### O7 addendum — Parallel Scan & Surrogate Prefilter

#### O7a — ProcessPoolExecutor batching

| Metric | Old (ThreadPool) | New (ProcessPool) | Improvement |
|--------|-----------------|-------------------|-------------|
| Speedup | 0.56x (GIL-bound) | **3.78x** (55 MJDs, 3-run mean) | ~7x better |
| Consistency | 5/5 identical | 55/55 identical | Full coverage |
| Workers | 4 (Thread) | 8 (Process) | Scales |
| Note | ThreadPool GIL limit | True multi-core; per-process cache load | |

The ProcessPool uses chunked batching (10 MJDs per chunk) — each subprocess loads the Horizons cache once and evaluates its chunk, minimising per-task overhead. At 8 workers on 20 logical CPUs, the scaling test shows linear speedup up to 2 workers (1.72x) then diminishing returns due to N-body solve being I/O + compute mixed.

**3-run repeated benchmark:** mean speedup = 3.78x (runs: 3.61x, 3.93x, 3.79x; std = 0.16). All 3 runs produced 55/55 identical results. The earlier single-run 5.72x was a cache-warm peak; the benchmark mean is the reliable reference. The old ThreadPool 0.56x result is retained as a negative baseline — it demonstrates why GIL-bound parallelism was abandoned for ProcessPool batching.

#### O7b — Ridge Surrogate Prefilter (no sklearn)

| Metric | Value |
|--------|-------|
| Method | Closed-form Ridge (no sklearn) |
| Target | r_p achieved (AU) — varies with t0 geometry |
| Training samples | 70 (stratified across 366-day scan) |
| Features | 6 geometric: moon_angle, moon_dist, v_inf, phase_angle, vel_align, angular_rate |
| Best α | 0.01 |
| Full R² | 0.8956 |
| MAE | 0.0589 AU |
| RMSE | 0.0834 AU |
| Top-5 recall | 20% (1/5) |
| Top-10 recall | 20% (2/10) |
| Top-15 recall | 33.3% (5/15) |

The surrogate is useful as a cheap prefilter: training 70 samples takes ~4 minutes of N-body solves, after which the full-year evaluation is instant (6-feature dot product). With R²≈0.9, it captures overall trends, but the moderate recall (33% top-15) shows that geometric features alone have limited power to predict N-body outcomes — genuine trajectory solves are still needed for the final decision.
